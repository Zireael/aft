# v0.58.0 change inventory (v0.57.2..v0.58.0)

Working file for the v0.58.0 release-notes rewrite. Source: `git log --no-merges v0.57.2..v0.58.0` (501 commits; the brief estimated 489), plus GitHub issues updated since 2026-09-23.

Method: every commit was assigned either to one user-visible change below or to the internal section. Each commit's added source lines were compared with the files at `v0.58.0` (lines of 30+ characters, data/doc files excluded). Everything listed as user-visible had 82-100% of its added lines present at the tag, except where a later commit in the same row rewrote it (451e7d53a 65% -> 9a49b7674; 3876b633c 37%, its in-memory eviction reverted by dd5700a8b; 7871f3ab2's description text was extended later and is present). Commits at 0-16% were checked by hand: 2a6a84962 is not shipped, e76fe7234/d2866dcc1 were reverted.

Old-notes column: `covered` = the published notes describe it; `missing` = not in the published notes; `covered (... missing)` = partly described.

Totals: 98 user-visible changes; 9 missing from the old notes; 4 partly covered. Wrong claims: none found. Spot-checked against `v0.58.0`: default `disabled_tools` (`aft_delete`, `aft_move`), `worktree.ram_overlay` default true, `removed_config_key:gh_read`/`gh_shim` rejections, 2,000-file delete budget, 15 s stall threshold, 2 reserved bind workers, 120 s unbound-build grace, `matcher=unloaded`, grep 500-char line cut, 5 s signal-exit bound, 1 KiB signature cap, the semantic notice text, `setup --harness opencode|pi|omp`, `aft backups purge`, "no LSP" footer, "git features off" header, OS metadata list. The old notes correctly omit 2a6a84962.

GitHub issues since 2026-09-23 not in the old notes: #360 (Windows console windows, @Cle2ment, fixed by 5782e879b). #358 and #357 were in the old notes without reporter credit (@iceteaSA). Not fixed in this release and left out: #335, #359, #363 (design notes only: e570cd35e, e8306524c), #365, #369 (open: OpenCode 2 footer shows "AFT starting…" until the first tool call because the bridge now starts lazily; a side effect of the plugin-startup change). #343 was retracted by its reporter. #327, #330, #332, #333, #334 were fixed in 0.57.x.
